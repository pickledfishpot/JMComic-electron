## 必修（后端 / Electron）

### 1. CORS 全放开，任意网页可驱动本机后端

- 位置：`backend/jmcomic_backend/main.py:82`
- 问题：`allow_origin_regex=".*"` + 服务端 session.json 无凭证要求 → 恶意网站可直接 fetch `http://127.0.0.1:18500+/api/*`（端口从 18500 起扫可预测），读收藏/历史、触发下载。
- 修复方向：打包后 `file://` 场景的 origin 是 `null`，白名单写法 `allow_origins=["null", <dev origins>]`，不要用正则全放开。

### 2. 下载 remove() 异步 rmtree 与重建任务竞态

- 位置：`backend/jmcomic_backend/services/download_manager.py:172`
- 问题：`remove()` 用 `run_in_executor` 异步 `rmtree` 且不等完成；`create_task` 去重已放行同书同章。删任务后立刻重下同一章 → 新 worker 写 `_eps_dir` 时执行器线程正在删 → `FileNotFoundError` 任务进 error，已写入的页也可能被事后删掉。
- 修复方向：删除与重建对同一目录加互斥（每目录删除锁/墓碑标记），或 remove 等待 rmtree 完成后再返回。

### 3. pending 任务删除后 id 在 _cancelled 永久泄漏

- 位置：`backend/jmcomic_backend/services/download_manager.py:168`
- 问题：`remove()` 无条件把 task_id 加入 `_cancelled`，但该集合只在 `_run_task` 的 finally 清理；pending 状态被删的任务永远进不了 `_run_task` → 反复"排队即删"导致集合无界增长。
- 修复方向：只有已入队/运行中的任务才需要标记取消；pending 直接删不入 `_cancelled`，或在 worker 取出任务时清理。

### 4. image_cache 锁清扫逐出未 acquire 的新锁

- 位置：`backend/jmcomic_backend/services/image_cache.py:38`
- 问题：`lock_for` 返回新锁之前做 >512 清扫（只保留 `v.locked()` 的锁），刚创建尚未 acquire 的锁被立刻逐出 → 看过 512+ 张图后 single-flight 失效，同一图片被并发重复拉取+反分割。
- 修复方向：先 acquire 再清扫，或清扫时排除"本次新建的锁"（如清扫前置入、用引用计数/LRU）。

### 5. waifu2x 异主结果导致忙等且超时保护失效

- 位置：`backend/jmcomic_backend/services/waifu2x_service.py:84`
- 问题：`sr.load(0)` 返回 done_id 不匹配的 truthy info 时，循环既不 sleep 也不检查 120s 超时（deadline 只在 else 分支），且全程持有全局 `_convert_lock` → 上次超时的滞留结果让下次 convert 忙等，CPU 100% 阻塞所有后续超分。
- 修复方向：不匹配分支也 sleep + 检查 deadline；异主结果直接丢弃继续轮询。

### 6. ~~backend-launcher 的 spawn 错误永远传不出去~~ ✅ 已修复（2026-09-04，随 Windows 打包问题一起）

- 位置：`electron/utils/backend-launcher.ts`

## 顺手修（前端）

### 7. loadComments(seq) 位置参数错绑 page 形参

- 位置：`renderer/src/views/BookDetailView.vue:56`
- 问题：签名是 `loadComments(page = 1, seq = detailReqSeq)`，调用写成 `loadComments(seq)` → 同一会话打开第二本书（seq=2）评论直接从第 2 页开始。
- 修复方向：改 `loadComments(1, seq)`。

### 8. 搜索下一页禁用条件用错每页大小

- 位置：`renderer/src/views/SearchView.vue:168`
- 问题：`page * result.books.length >= result.total` 把当前页条目数当每页大小 → 尾页不满员时（如 total=45 第 3 页 5 条）`3*5=15 >= 45` 为 false，还能点出空白第 4 页。
- 修复方向：用固定 pageSize 判断，或以后端返回的 total/count 计算 hasMore。

### 9. replace 跳登录后回不到原书页

- 位置：`renderer/src/views/BookDetailView.vue:86`、`renderer/src/views/FavoritesView.vue:77`
- 问题：未登录点收藏改 `router.replace("/login")` → 历史栈从 `[home, /book/123]` 变 `[home, /login]`，登录成功 `goBack()` 回到 home 而非原书页。
- 修复方向：改回 push（登录后 back），或登录成功显式跳回来源路由（携带 redirect 参数）。

### 10. scripts/dev.ts 在 Windows 上 ENOENT

- 位置：`scripts/dev.ts:10`
- 问题：spawnSync/spawn 调无扩展名 `node_modules/.bin/tsc`（无 `shell:true`、无 `.cmd` 回退）→ Windows 下 Node 不做 PATHEXT 解析，CreateProcess 失败，`process.exit(build.status ?? 1)` 静默退 1。
- 修复方向：`process.platform === "win32"` 时用 `tsc.cmd`，或 `shell: true`。

### 追加 3：反分割层数算错——%8/%10 取反（2026-09-04，已修复）

- 现象：打包后阅读器图片仍乱序，同一张图被切成多层且层间顺序不对。
- 根因：`deslice.py` 移植 `tool.py ToolUtil.GetSegmentationNum` 时把两个区间的模数写反了——`epsId > 421926` 应为 `% 8`（写成了 `% 10`），`268850 <= epsId <= 421926` 应为 `% 10`（写成了 `% 8`）。模数错 → 分割数 num 错 → 按错误条高等分再倒序贴回，层边界全错位。现有章节 epsId 基本 > 421926，全中招。粘贴循环本身与 qt 逐行一致，无问题。
- 交叉验证：qt `tool.py:900` 与依赖库 `jmcomic.jm_toolkit.JmImageTool.get_num`（`x = 10 if aid < 421926 else 8`）一致；修复后随机 300 组样本与官方库 0 mismatch。
- 修复：`deslice.py` 换回正确模数；`test_reader.py` 三个用例原先按错误实现写期望值，一并修正。
- 教训：移植"魔法常量"算法时应直接以官方库/原实现做 parity 测试，而不是按移植后的代码写期望。
